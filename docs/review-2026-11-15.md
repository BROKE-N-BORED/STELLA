# STELLA — Full-product review, 2026-11-15

**Reviewed:** STELLA v0.24.0, head `6d558196`, live tree
`~/workspace/stella/`.
**Suite at review time:** 1397 passed / 64 skipped, verified green
2026-11-15 from a fresh unzip (the 1 failure in that run was a
confirmed load flake). Static census: 1462 items.
**Companion file:** `docs/stella-review-task-list-2026-11-15.md` —
129 tasks (R1–R129), 0 P0, 23 P1, 52 P2, 54 P3.

## How the review was done

Nine auditors, one per area, each working read-only on scratch copies
and driving the real product wherever the sandbox allowed it: training
engine, GGUF/requant/distill, profiles/projects, GUI, chat/providers,
CLI, installer/doctor, sleep/probe/docs, and tests. Every finding in
this report carries evidence — a file:line, a failing probe, or a
measured behaviour — and the task list traces every finding to exactly
one task (verified mechanically; see the coverage map in the task
list). The review followed the BNB playbooks for full-product review
(S5), audit-each-one-combine (S64), and audit-findings-task-list-merge
(S65), with the coordinator's own probes for the areas the sandbox
blocked (the profile probes were run by the coordinator after the
auditor's sandbox refused writes). The 194-task audit list is closed:
nothing in it was re-filed, and where a DONE claim no longer holds it
is named as such rather than quietly re-filed. OST items were kept out
entirely.

One area cost three attempts: the GUI auditor drove the GUI and took
30 screenshots but died before writing (database pool timeout), its
replacement died at bootstrap, and the second replacement reused the
screenshots and probes and wrote the report. Nothing in the GUI area
was skipped.

**What "verified" means here.** "Verified on the VM" means measured or
probed in this sandbox. "Never verified on his PC" means exactly that:
five real-PC tails are still open (see below) and are filed as
hard-gated tasks, not claimed as verified.

## Verdict

STELLA v0.24.0 is a sound product with a real list of improvements and
no emergencies. **Zero P0s**: nothing in the review loses data, bricks
an install, or blocks normal use. The suite is green, the secrets
sweep is clean, the v0.24.0 fixes all hold, and the GUI is the
redesign the audits asked for. What the review found is a layer of
honesty gaps: three DONE claims that are false in v0.24.0, two
provider lists that rotted while nobody was looking, one feature
(sleep) whose payoff has no path, one safety gate that is never
enforced, and one core purpose (training) that still cannot be set up
without a terminal. Those are the P1s. The P2s are correctness and
polish; the P3s are nice-to-haves. Nothing here says the project is in
trouble — it says the next round of work is well defined.

## Top 10 headline findings

1. **The New Profile dialog picks the first model by itself.**
   Qt's focus behaviour selects row 0 after `show()`, defeating the
   `setCurrentRow(-1)` fix (`stella/gui.py:413`); pressing Enter on a
   freshly shown dialog created a profile for `lfm3:1.7b`, a model the
   user never picked (probe3 ENTER-TEST). T18 is marked DONE with the
   claim "Enter with no pick does nothing" — false in v0.24.0. Both
   T18 tests never show the dialog, so the suite stays green
   (`tests/test_gui.py:2670, 2710`). **R1 (P1).**
2. **The trash has no way back, and the documented way back is a trap.**
   No Restore button, no restore function (`stella/gui.py:2447-2614`,
   `stella/model.py:474-530`); T23's DONE claim ("restore … from the
   Trash window") holds only for purge. The help text says to move the
   folder back — but a dated trash folder moved back as-is is listed
   yet unopenable (`get_profile` uses the folder name; probe P14).
   **R2 (P1).**
3. **Sleep adapters are stranded.** GGUF export merges only the project
   adapter or a checkpoint (`stella/gguf.py:704-715`; zero "sleep"
   references in `gguf.py`), yet the sleep docstring, README, and How
   to Use all claim sleep adapters merge "through the existing GGUF
   export path". The whole point of a sleep cycle has no path.
   **R3 (P1).**
4. **The refusal probe gate is never enforced.** Nothing auto-probes
   after training; export never consults probe results and proceeds
   with none (`stella/gui.py:9042-9048`); the T148 preview is a choice,
   not a block. A governing-seat tune can reach Ollama without ever
   passing the gate. **R4 (P1).**
5. **Vision models silently lose their vision.** Zero `projector` /
   `mmproj` references anywhere in the tree. Requanting
   `qwen3-vl:2b-instruct` would register a text-only copy with no
   warning; export cannot load a VL model at all. **R5 (P1).**
6. **The Groq and Gemini model lists are stale — the defaults error.**
   Groq: both Llama models (including the default
   `llama-3.3-70b-versatile`) went Enterprise-only on 2026-08-16;
   self-serve is now the two GPT-OSS models. Gemini: `gemini-2.0-flash`
   shut down 2026-06-01 and the 2.5 models 404 for new keys since
   2026-09-18. Confirmed against the providers' own pages on
   2026-11-15. **R11, R12 (P1).** The lasting fix — the lists have no
   freshness mechanism — is **R51 (P2).**
7. **There is no click-only way to install training.** No `.desktop`,
   no GUI button; every surface says `bash install-training.sh`
   (`gui.py:6353`, `cli.py:374`, `train.py:54`, `howto.py:36, 315`,
   `provision.py:259`). The thing Stella is for cannot be set up
   without a terminal, against the immutable installer rule.
   **R13 (P1).**
8. **The doctor has two live bugs.** It writes a launcher with a
   literal `Icon=path` when hicolor icons are absent
   (`doctor.py:154`), and the error is sticky — a second run reports
   `OK launcher` / `OK icon` with `Icon=path` still in the file
   (`doctor.py:143-151`). It also misdiagnoses every unmapped libxcb-*
   library as libxcb1 (`doctor.py:76`), so the user installs the wrong
   package. Both proved live. **R9, R10 (P1).**
9. **The RAM recalibration is unproven at LFM3 scale and on his PC.**
   The v0.24.0 recalibration rests on ONE 0.5B probe run, never
   measured at 1.7B scale or on his machine; if the true resident
   share at 1.7B is 0.8 not 0.5, the true total is ~1 GB over the
   4.34 GB estimate. The LFM3 proof run is still the open item.
   **R19 (P1, hard-gated).**
10. **Four tests fail on a plain install, so CI's base job would go
    red.** `tests/test_train.py:1411, 1440, 1460` call
    `monkeypatch.setattr("huggingface_hub.HfApi")` with no skip gate;
    `:1481` asserts 2e9 but gets `None`. Masked because the test VM
    happens to have `huggingface_hub`; a base install has only
    PySide6. Contradicts run_tests.sh's "a base install still goes
    green". **R16 (P1).** Two more tests are genuinely fragile with
    proven mechanisms (the Ollama-down settings test races a live
    background refresh; the press-dip test misses the dip under load,
    5/10 probe runs) — **R17, R18 (P1).**

## Per-area verdicts

**1. Training engine — sound, with the proof run still open.**
11 findings (1 gated P1, 5 P2, 5 P3). All audit-08 training-side fixes
hold; resume genuinely restores optimizer + step + RNG; the honesty
table is measured (LFM3 rank8/seq1024 4.34 GB fits, seq4096 9.12 GB
refused, 3B fits, 8B refused even rank4/seq512). The gaps are around
the edges of a run: the dry-run `fits` answer ignores dataset RAM
(R24), offline cached weights are refused (R25), resume after a
dataset edit silently trains the wrong rows (R26), a hard crash leaves
status `"training"` forever (R27), and `method: full` is still
settable via CLI and silently trains LoRA (R28). The open item is the
one that matters most: the recalibration has never been measured at
LFM3 scale or on his PC (R19).

**2. GGUF / requant / distill — the v0.24.0 fixes hold; three sharp
edges remain.** 16 findings (2 P1, 7 P2, 7 P3). The parser was verified
live against the real lfm3 blob (Q5_K/5.5 bpw, 3.21 s, 31 MB RSS).
The P1s are the whole-blob read for a 4-byte check (1.05 GB peak for
the 1.1 GB blob; a 2.7 GB model would cost 2.7 GB transient on his
8 GB PC — R6) and vision models silently losing vision (R5). The P2s
are mostly estimates and failure handling: the parser's near-tie
(136 Q5_K vs 133 F32), distill aborting the whole run on one failure,
export with no disk guard and an estimate that omits the F16
intermediate, requant's estimate omitting Ollama's blob copy, cleanup
only on `StellaError`, no requant timeout, and teacher answers
silently cut at 1024 tokens (R29–R35).

**3. Profiles / projects — solid core, one trap, one crash.**
13 live findings (2 P1, 5 P2, 6 P3) plus 1 withdrawn. The T54 rule is
in place and correct (confirmed by probe); zip-slip refusal is
confirmed live. The P1s are the trash trap (R2) and invalid UTF-8
crashing the whole list instead of one damaged row (R7). The P2s: a
misleading recipe-import warning, model write paths that don't
type-check (`dependencies="torch"` shreds to characters), export not
validating what it writes (Stella exports packages its own verify
refuses), import with no zip-bomb cap (a 66 KB zip extracted to 67 MB
with no cap hit), and clone silently dropping damaged projects
(R36–R40).

**4. GUI — the redesign mostly holds, with one real regression.**
14 findings (1 P1, 6 P2, 7 P3). Of audit-09's 26 R-tasks, 24 hold, 1
holds in part (R9's plan half, code-only), 1 does not hold (R4 — the
New Profile pre-select, R1). The brief's flow is above the fold at
both sizes, training settings are gone from every screen (0 hits in a
677-string sweep), the checklist gates honestly, the menu bar is real
with correctly disabled actions, the live loss curve and finish moment
work, tooltips and shortcuts and both accessibility presets work. The
P2s: a stale status-bar message (R41), a transient Settings overlap
(R42), the fit verdict calling every model "Too big for this PC"
(R43), the run-button row clipped at 1366x768 (R44), Resume enabled
with no checkpoints (R75), and the missing Restore button (R2). The
BNB library's Drop 3 entries (025–036) were checked for the first
time: 8 in (4 satisfied, 4 with gaps — R96, R97, R98, R2), 4 out
(025, 026, 032, 034, with reasons recorded in the audit).

**5. Chat agent + providers — the agent works; the provider lists
rotted.** 16 findings (3 P1, 6 P2, 7 P3). The agent loop was verified
end-to-end over real HTTP (17/17 fake-server checks); the 12-call cap
is enforced exactly with a plain-words stop; all 17 tools wrap real
engine functions; secrets are clean (keys only in `providers.json`,
mode 0600, atomic write, never logged). The P1s are the stale Groq and
Gemini lists (R11, R12) and CLI chat swallowing all narration (R14).
The P2s are agent-loop details: a typed cloud pick dropped when
Ollama is down, history never truncated (re-sent and re-paid every
turn), tool-block parsing gaps, no step tracking, and a model-list
re-fetch on every call (R45–R50). Missing outright: a freshness
mechanism for the lists (R51) and any cost visibility (R106).

**6. CLI — disciplined errors, patchy parity.** 14 findings (1 P1,
6 P2, 7 P3). The `stella:` one-line error discipline holds across ~50
probed paths; `--steps` is a real cap; `--quant BOGUS` fails in under a
second naming all 35 valid values; `--json` is valid JSON on all 6
commands that claim it. The P1 is `sleep` with no dataset sending the
user to "the Train panel" (R15 — the T111 guard test greps only
`cli.py`, so it missed this). The P2s: `--json` silently ignored on
~25 commands, export printing "Package size: about 0 bytes." before
failing, chat errors on stdout and no CLI way to save a provider key,
no clone commands, and a nameless-profile warning that contradicts the
row shown (R52–R56).

**7. Installer / doctor / uninstall — honest and atomic, with two
doctor bugs and one rule gap.** 18 findings (3 P1, 7 P2, 8 P3). The
audit-06 P0s are genuinely fixed; the double-click installer exists
and `%k` expansion was proven via direct libgio calls (the call Nemo
uses); zip modes are perfect (all 122 entries conform); install.sh is
honest and atomic; re-install never touches `~/.stella`; the doctor's
EGL fix holds and all 14 map entries are real Ubuntu noble package
names. The P1s are the two doctor bugs (R9, R10) and the missing
click-only training install (R13). The P2s include the uninstall
removing a launcher without checking it points at this install (an old
folder's uninstall breaks the new install after an upgrade), a
no-network install waiting minutes in silence, and a training
preflight that understates the peak (R57–R63). One methodology note:
`gio launch` passed `%k` empty where direct libgio passed the correct
path — `gio launch` is not a faithful double-click simulator, which is
why the literal Nemo double-click stays a hard-gated tail (R22).

**8. Sleep / probe / docs — the sleep feature works; its payoff and
its gate do not.** 20 findings (3 P1, 9 P2, 8 P3). The sleep rank cap,
the +10% boundary (exactly +10% is NOT degraded), pause/resume, and
dreaming's clean skip (closed port, bad host, HTTP 500, garbage body,
no-text body all skip without raising) all check out. T30's 6
misjudged replies and the empty-string vacuous gate pass are fixed and
test-pinned. The P1s are the stranded sleep adapters (R3), the never-
enforced probe gate (R4), and the orphan-heal hash drop (R8). The P2s
are probe judgement residuals (9/11 new edge cases misjudged), a gate
that trusts a stale delta, sleep cycles piling up with no delete, a
pre-train warning that only fires for marked profiles, the CLI/GUI
gating disagreement, and the README and How to Use refreshes (R64–R70).

**9. Tests — green on the VM, red on a base install, two fragile
tests.** 10 findings (3 P1, 5 P2, 2 P3). The suite is green where it
runs, the skips are all legitimate (63 × "training stack not
installed" + 1 × "desktop-file-validate not installed"), and the
secrets sweep is clean. The P1s are the base-only failures (R16) and
the two fragile tests with proven mechanisms (R17, R18). The P2s: a
v0.24 fixture that opens the real `~/.stella` store, HEAD/ranged-GET
helpers never really executed, 12/30 plain-words error-map entries
untested, and fixture teardown that does not wait for jobs (R71–R74).
CI has no scheduled runs and never runs desktop-file-validate or
shellcheck (R120). The carried items resolve here: the import
job-wait flake is confirmed harness-only, and the JobWorker lifetime
gap could not be constructed as a product defect — every window waits
for its workers in `closeEvent`.

## Withdrawn findings and corrections

- **A3-F6 (withdrawn).** The profiles auditor claimed a crafted
  package could escape via symlinks. A probe disproved it: the crafted
  outside-symlink package is refused
  (`StellaError: export manifest: file entry 'checkpoints/step-50/
  state.json' escapes the package`). The leaf functions do follow
  symlinks, but the attack as constructed does not work, and
  in-package symlinks point at content the attacker already controls.
  Withdrawn with evidence; not a task.
- **Groq's free tier is not gone.** The chat auditor's rationale said
  every cloud chat costs money. That is wrong: a free tier still
  exists on the remaining self-serve Groq models (rate-capped; e.g.
  GPT-OSS 120B at 30 req/min on the free plan). The correct statement
  is that the two Llama models left the free/dev tiers. R106 uses the
  corrected rationale.
- **The area has 17 tools, not 18.** The brief said 18; TOOL_HELP,
  the handlers, and TOOL_NARRATION all count 17. The 18th was
  `set_project_settings`, removed in v0.11.0 (T16 DONE). Report note
  only, not a task.
- **The GUI audit withdrew 14 look-alikes** after probing (an "Idle"
  dot and Go-enabled-during-run were probe artifacts; "Dataset: True"
  was a fixture boolean; the 2.9 KB "partly downloaded" was honest
  leftover bytes in the shared HF cache; import-preview KeyErrors were
  fixture artifacts). They are recorded in the audit so they are not
  re-filed.
- **Known quirk, not a finding:** `malloc_consolidate(): unaligned
  fastbin chunk detected` at interpreter shutdown after the GUI suite,
  exit code stays 0, present since v0.3.1.

## Avoid list (ideas that would break the hard rules)

  HDD is the failure the estimates exist to prevent.
- Do not add a cloud GPU training path as a default: hard $0.
- Do not bundle per-profile virtual environments without Joshua's
  T182 decision.
- Do not add a background network call to keep the model lists fresh
  without his say-so: the product is offline-first; R51 says so.
- Do not add anything that needs a terminal to install, run, or
  repair: the click-only rule is immutable.
- Do not make the GUI a web UI: native Qt window only.
- Do not chase 8B models on his PC: refused even at rank 4 / seq 512
  (10.74 GB).
- Do not add a toast/snackbar surface: the status bar is the one
  status surface (the real issue is its staleness, R41).

  the library's preference.
