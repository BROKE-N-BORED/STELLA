# Stella v0.34.0 — full-product review, 2026-11-19

Reviewed: Stella v0.34.0, commit 64269ca8, from the shipped zip
(stella-v0.34.zip, SHA-256 01e4b920…). Review only — nothing was fixed,
nothing was changed in the product. Every task this review produced is in
docs/stella-review-task-list-2026-11-19.md (and the plain-text copy,
docs/stella-review-task-list-2026-11-19.txt). All 83 tasks are open;
none have been started.

## Verdict

The front door is genuinely toy-simple, and the core flows work. A brand-new
user can install from the zip, open Stella, follow the first-run checklist,
make a profile with one pick, get a one-tap download offer for a known model,
attach a report card, and finish an export with the new "Put it in Ollama"
button — all of that was driven for real in the shipped program and works.
There are **no P0 findings**: nothing found breaks a core flow or loses data,
and the areas rewritten since the last review pass their targeted tests.

Underneath that, the review found **85 findings: 0 P0, 18 P1, 37 P2, 30 P3**,
merged into **83 tasks** (two pairs of findings share one fix). The P1s are
not scattered — they cluster in four themes:

1. **The newest features (v0.30.0–v0.34.0) have correctness holes at their
   edges.** The requant quant table is shifted by one id, so "Make smaller"
   misreads what a model already is and can re-compress an already-small
   model while believing it is safe. The live Hugging Face lookup offered
   three unrelated 4–9B models as the match for a known tag. A report card
   can be credited to the wrong model, and attaching many cards collapses a
   profile's strengths to whichever single card is newest. A probe pass
   survives retraining, so the refusal gate can wave through an adapter it
   never measured.
2. **Chat can misreport what happened.** A plan runs on any message starting
   with "yes" — including "yes but not yet". Failed template steps are
   reported as "all done". A repo can be set and downloaded on the strength
   of a confirm flag inside the model's own tool call, with no offer ever
   shown to the user.
3. **The no-terminal rule is still broken by a layer of older messages.**
   The rule was set after the last review closed, and a set of pre-rule
   messages across the main window, the Train panel, the export probe gate,
   and the installer still hand the user terminal commands — including one
   permanent line on the main screen and one failure popup whose only
   instruction is a command the user cannot type.
4. **A few success reports are not true.** Distill reports success counting
   rows a failed run never produced. Requant deletes its only copy of a
   result after an Ollama create that was "verified" by exit code alone.
   Uninstall says removing the folder "finishes removing it" while leaving
   ~2 GB of downloaded wheels behind.

None of this needs a redesign. The shape of the program is right; these are
specific, fixable defects, each with evidence and a named fix in the task
list.

## How the review was done — what was driven, what was read

Nine audits ran in parallel, each with its own scratch space; the product
tree was read-only throughout. Working notes, screenshots, and probe scripts
are under ~/workspace/stella-review-2026-11-19/.

**Driven for real, as a user (the shipped zip, installed fresh):**

- The real GUI, offscreen at 1366×768 (Joshua's screen), through scripted Qt
  drives with screenshots eyeballed at every step — 60+ screenshots across
  two GUI audits. First run and checklist; New Profile in all three flavours
  (bridge-mapped tag, unmapped tag, no-repo tag); the mismatch guard; the
  profile window's simple view and Details flap; report cards attached,
  removed, and read back as strengths; project creation; dataset picking
  (valid and damaged); Train panel setup and dry run; Sleep, requant,
  distill, and probe panels walked as far as a user can; export GGUF and the
  "Put it in Ollama" finish button, including the name-taken question
  answered both Yes and No; Settings; How to Use read topic by topic.
- One **real lookup against the live huggingface.co** (for
  dolphinlabs/qwen3.5-uncensored:latest) — this produced finding GA-F1 / task
  N2. Other Hub behaviour used a fake Hub server for determinism.
- Ollama was faked (a stand-in binary/server) for the export and
  Put-it-in-Ollama drives.

  launchers, the failure popups, and uninstall.
- The CLI as a user: all 46 subcommand helps plus ~70 live invocations
  against scratch Stella homes, including confirms answered both ways.

**Read in full and probed with targeted scripts/tests:**

- The training engine, sleep, and the refusal probe; the GGUF / requant /
  distill / Ollama pipelines; the v0.30–v0.34 code (wheel fetch, the bridge
  and mismatch guard, strengths, the report-card parser, the Hub lookup);

- Targeted test chunks only (the v0.34.0 full-suite result stands): the
  v0.30–v0.34 test files (129 passed), test_gui.py in full twice (376 passed
  both runs), and the probe/sleep/train test files for the engine audit.

**Not done — stated plainly:**

- **No real training run.** This VM has no torch anywhere, so training was
  walked through setup, dry run, and the missing-packages path only; the 82
  torch-path tests stayed skipped. A real run remains PC-gated (see R19–R23

- **No real Ollama exchange.** The VM's Ollama on 127.0.0.1:11434/11435
  refused connections all day, for every auditor. Chat was audited by code
  read plus scripted probes of its tool/confirm logic; the export and

- **No real weight downloads** (fake Hub, apart from the one real lookup
  above) and no real-PC checks: the double-click installer on real Mint and

Environment failures during the review (VM write bursts, load flakes) were
diagnosed as environment and are not findings; one test_gui run under load
showed two progress-assertion failures that passed solo and in two other
full runs — a flake, not a regression.

## Findings by area

Task numbers (N1–N83) refer to the merged task list. Severity counts are the
raw findings before merging.

### GUI — first run, profiles, downloads (audit-gui-a: 6 findings, 1 P1 / 1 P2 / 4 P3)

The front door is in good shape: first run, the checklist, one-pick profile
creation, the bridge one-tap offer, the mismatch guard, the simple profile
view, and report-card attach/remove all drove clean (see "What is clean").
The one P1 is serious: **the live Hub lookup, asked for
dolphinlabs/qwen3.5-uncensored:latest against the real Hugging Face,
offered three unrelated repos** — two 9B/4B "heretic" builds and a Qwen3.5-9B
— under the words "Stella found X on Hugging Face for this model. Use it?"
(N2). A user who trusts that sentence downloads the wrong model. The P2 is
the inconsistent no-repo ending: from Download it sends the user hunting by
hand and does not open the profile window; from "Set the model source…" it
does (N19). The P3s are a stuck "Looking on Hugging Face…" status line
(N56), "updated unknown" on a new profile (N57), two big empty boxes
dominating the simple view (N58), and the repo field's placeholder being a
real repo belonging to a different model (N59).

### GUI — main window, jobs, chat window (audit-gui-b: 14 findings, 3 P1 / 5 P2 / 6 P3)

Three P1s, all about words that break the rules. The main screen
**permanently shows a terminal command** ("Training settings are changed
from the terminal: stella update-project … --seed 7") whenever a project's
settings differ from the template (N11). When the training packages are
missing, the message **tells the user to run a shell script in a terminal**
— and also points at a "Train panel" that does not exist (N12). And the
export probe-gate refusal speaks "governing seat" jargon, hands over another
CLI command, and following its own instruction loops back to the same
refusal (N13). P2s: a Step cap number on the main screen, against the
brief's "the user never sees training settings" (N20); the offline Chat
window contradicting itself and suggesting an unusable cloud model (N21);
the unexplained "Step 4 of 8: Recipe." line in chat (N22); the ~2,020 px
main-window scroll with export/probe far below the fold (N23); and
"Estimate unavailable." with no reason or next step (N24). P3s cover finish
cards that still look busy when done (N60), one-bad-line-at-a-time dataset
errors in parser language (N61), the Put-in-Ollama success sentence pointing
at Code Forge's model list (N62), "pull the model" CLI wording (N63), the
probe status line using the internal slug (N64), and the New Project
dialog's pre-chosen template and bare "OK" (N65).

### Training engine, sleep, probe (audit-engine: 10 findings, 2 P1 / 5 P2 / 3 P3)

P1: **a passed probe survives retraining** — training replaces the adapter
but never invalidates the saved probe result, and the gate checks only the
saved numbers, so an export gate can pass on measurements of an adapter that
no longer exists (N5). This is a hole in the previously closed R4 item,
proven by probe. P1: **sleep can dead-end forever** — a crashed checkpoint
save's leftover folder counts as "has checkpoints", after which resume
refuses with "nothing to resume" on every later try (N17). P2s: chat-run
probes are stamped as gate runs even for non-governing profiles (N25); the
refusal judge scores two plainly compliant answers as refusals (N26);
dreaming that produces nothing usable is reported as if it worked, and no
dream outcome is saved in the cycle report (N27); the --steps cap is ignored
by the disk guard and dry run (N28); the merge RAM guard judges only the
fixed 8 GB ceiling, never free RAM, and replay/probe load the base with no
RAM check (N29). P3s: a damaged probe-results file can pass the gate on a
missing total (N66); the sleep threshold accepts nan/negative values (N67);
validation loss silently covers at most 50 rows (N68).

### Pipelines — GGUF, requant, distill, Ollama (audit-pipelines: 8 findings, 3 P1 / 3 P2 / 2 P3)

P1: **the requant quant table is shifted by one** — ggml id 9 (Q8_1) is
missing from the table, so every id from 9 up reads one step too small: a
real Q4_K model reports as "Q5_K", a Q8_K as "IQ2_XXS", and the
double-compression warning for Q8_K can be silently suppressed when its
byte-vote is won by F32. The tests encode the same wrong table, so the suite
cannot catch it (N1). P1: **distill's success gate counts stale rows** — the
gate reads the whole output file including rows from earlier runs, so a run
whose teacher failed every prompt still reports success and re-points the
project's dataset (N7). P1: **requant deletes its only copy** of the result
after an `ollama create` checked by exit code alone — a no-op create that
exits 0 produces a success report and a deleted work folder (N6). P2s: the
closed R30 "teacher was slow, not down" wording is dead code on the real
path (N30); requant's create has no timeout (N31); convert/quantize outputs
are never checked to actually be GGUF files (N32). P3s: the Modelfile FROM
line's single-quoting is unverified against real Ollama (N69); a failing
distill prompt burns two full timeouts in silence (N70).

### The v0.30–v0.34 code (audit-newcode: 13 findings, 2 P1 / 8 P2 / 3 P3)

P1: **the report-card parser skips the model-match check for two of its
shapes** — probed against all 175 real OST files, every parseable card also
parses under a wrong model hint, so a bonsai-2 card attached to an LFM3
profile is presented as LFM3's measured strength, breaking the v0.32.0
"flagged, never applied" promise (N3). P1: **strengths come from the single
newest card only** — attaching all 11 models' full OST runs yields one
weakness and nothing else, where OST's own aggregation shows 9 strengths
and 4 weaknesses for the same model (N4). P2s: the bridge offers another
size's repo labelled as the model's own, and strengths does the same for
other sizes (N33, merged); the mismatch guard never runs before training on
already-downloaded weights, and a deliberate "Keep" is not remembered (N34);
the built-in table claims LFM3 is good at long documents while OST measured
0% (N35); the Hub lookup says "none found" when the Hub actually failed
mid-search (N36); the "offerable" check passes a repo whose real weights are
GGUF (N37); provision calls a dangling-symlink snapshot "ready" (N38); a
local weights folder is treated as a Hub repo id (N39); cloning a profile
silently drops its report cards and notes (N40). P3s: the import
cards-only-for-new-profiles rule is stated nowhere (N71); wheel-fetch cache
edges (N72). Re-proven clean in this area: the wheel %2B fix, the path
traversal guard, trash restore, zip-slip refusal, checksum tamper detection,
autoconfig staying inside its envelope, and no secrets anywhere in the new
code.

### Chat and providers (audit-chat: 10 findings, 3 P1 / 3 P2 / 4 P3)

P1: **a plan runs on any message starting with "yes"** — "yes but not yet"
executed the whole plan, and the check runs before the refusal check (N10).
P1: **failed template steps are reported as success** — the loop never marks
a step failed, so the final message claims "all done" over steps that
errored (N8). P1: **the repo confirm is not a real confirm** — setting a
profile's repo checks only a `confirm: true` flag inside the model's own
tool call, with no record that an offer was ever shown; the merged task also
covers the related finding that a plain confirm on a multi-candidate offer
can pick a repo the user never saw named (N9). P2s: a removed chat model
(404) dead-ends in raw provider wording, and the stale-list warning only
ever shows in Settings (N41); unexpected errors echo raw exception text
unscrubbed (N42); saving a key over a damaged providers.json silently drops
the other keys from the live file (N43). P3s: a duplicated tool block runs
twice with real side effects (N73); a query string in a custom provider URL
makes a nonsense endpoint (N74); one malformed tool block discards the whole
turn (N75). Clean here: all 17 tool handlers match the real engine
signatures, providers.json is written atomically at mode 0600, keys never
leak into output, the 12-call cap is exact, and the CLI-narration fix from
the last review still works.

### CLI (audit-cli: 9 findings, 1 P1 / 5 P2 / 3 P3)

P1: **`sleep-delete` and `sleep-prune` delete permanently with no
confirmation and no --yes flag** — every other delete in the product asks;
these two, which destroy sleep cycles, do not (N16). P2s: the help promises
--json everywhere except 7 commands, but 5 more refuse it with an untrue
reason — and two of them already contain finished, unreachable --json code
(N44); train --dry-run --json failures print no JSON envelope (N45);
prune/delete-checkpoint report success or blame the wrong thing for a
profile that does not exist (N46); the CLI never got the "Put it in Ollama"

(N48). P3s: --quiet does nothing on requant/export-gguf (N76); --verbose
changes nothing for ordinary failures (N77); a deliberate No exits 1 on
deletes but 0 on the replace question (N78). Clean: the earlier review's CLI
items (R14, R28, R9/R10 doctor wording) all still hold.

### Installer, launchers, uninstall (audit-installer: 6 findings, 2 P1 / 2 P2 / 2 P3)

The scratch install from the shipped zip works end to end (exit 0, pinned
PySide6 exact, double-click launchers proven). P1: **uninstall leaves the
~2 GB wheel cache behind** — it never removes, offers, or mentions
~/.cache/stella/wheels, yet tells the user deleting the folder "finishes
removing it" (N15). P1: **the run.sh failure popup's only instruction is
"Run: bash install.sh"** — a command, in a popup, for a user who never uses
a terminal; it never names the double-click Install Stella icon that is the
actual fix (N14). P2s: every installer/doctor retry message has the same
"run bash install.sh again" shape (N49); the training install's first step
is minutes of silence with no progress line or network check (N50). P3s:
the wheel failure line shows a raw Python error (N79); three launcher
scripts ship in the zip without the executable bit (N80).

### Docs and How to Use (audit-docs: 9 findings, 1 P1 / 5 P2 / 3 P3)

How to Use is mostly accurate — every topic was checked against the code,
and the v0.30–v0.34 regression spot-checks passed (129 targeted tests; the
R1 child-simple profile behaviour confirmed in the GUI drives). P1: **the
Troubleshooting topic names the wrong button** ("press Download model" in
the profile window — that button is "Download the training files"; "Download
model" is on the main window), presents the manual Hugging Face hunt as the
normal path although the same guide says Stella searches for you, and gives
"for example LiquidAI/LFM3-1.7B" — the exact string that was once typed into
the wrong profile (N18). P2s: the README proof run points at a "Start
training" button that does not exist (N51); the README's feature record
stops at v0.24.0 and never mentions report cards, the live lookup, or Put it
in Ollama (N52); the README still teaches assigning a role by hand, which
v0.31.0 abolished (N53); the profile window's tag help contradicts the guide
and the code about the refusal probe (N54); How to Use never mentions the
mismatch warning, and its Bridge topic predates the live search (N55). P3s:
the export list omits probe results its own import list includes (N81);
FORMAT.md's example manifest is five versions stale (N82); "validation
loss" is used once and explained nowhere (N83).

## What is clean

Worth stating plainly, because a review that only lists defects misleads:

- **First run and profile creation** are as simple as the brief demands:
  one pick, everything else optional, plain words, nothing pre-selected.
  The v0.31.0 child-simple profile window passes its regression check — the
  technical fields sit behind one closed Details flap.
- **The download flow for known models** — bridge offer in one tap, the
  mismatch guard's wording and one-tap fix, the honest no-repo ending's
  message itself — all drove correctly.
- **Report cards** attach, list, and remove cleanly in the window, and OST
  cards in all five real shapes parse (the defects are in matching and
  merging, N3/N4, not in the mechanics).
- **Export and Put it in Ollama** work end to end, including the name-taken
  question defaulting to No on both the button and the CLI.
- **The installer** installs the shipped zip cleanly from scratch, and the
  earlier review's installer/doctor items (R9, R10, R13, R58) and the
  v0.30.0 wheel fix all still hold.
- **Storage safety**: trash restore works, zip-slip is refused, checksum
  tampering is detected, providers.json is atomic and private, and no
  secrets appear anywhere in code or output.
- **Targeted tests**: v0.30–v0.34 test files 129 passed; test_gui.py 376
  passed in two full runs. No regression was found in the closed 2026-11-15
  items that touch the rewritten areas — except the two noted in the text:
  the stale probe pass (N5, a hole in R4) and the dead R30 wording (N30).
